# BountyHaven 공식 아트 기준 · main-art-v2

## 0. 시각적 우선순위

사용자의 최신 명시적 지시 → 승인된 원본 이미지 → 이 문서와 `art/canonical/style_contract.json` → 작업별 프롬프트 → 과거 기술 문서 순서입니다. 초기 `ink_art.gd`와 엔진 캡처, 다른 SLOWRAIN 게임의 복셀·청사진 스타일은 신규 아트의 근거가 아닙니다.

기존 20장의 승인 범위는 **그림체와 전체적인 시각 방향**입니다. 화면에 들어간 임시 수치·캐릭터명·정원·카메라·게임 기능까지 확정한 것이 아닙니다. 이 가이드는 그림체를 새로 바꾸는 리디자인이 아니라 승인 방향으로 복귀하는 정리입니다.

## 1. 정확한 목표

**정교한 잉크 드로잉과 수채·안료 채색으로 그린 산업 SF 개척지. 거대한 건축과 작은 여행자. 따뜻하게 살아가는 함선 내부와 차가운 우주의 대비.**

'수채화'를 빈 종이 위 파스텔 도형 몇 개로 해석하지 않습니다. 승인 화면은 배관·골조·난간·도크·패널·천·가구가 충분히 묘사되어 있고, 가까운 사물의 어두운 윤곽과 밝은 원경이 대비됩니다. 선은 구조를 읽히게 하고 안료는 재료와 대기를 만듭니다. 전경까지 전부 흐리거나 빛바래게 만들지 않습니다.

## 2. 하나의 master, 상황별 primary

공통 최상위 master는 **01 Rust Harbor**입니다. 같은 종류의 새 장면이라면 먼저 01의 실제 원본을 연 뒤 필요한 상황 기준을 추가합니다.

| 구분 | 번호 | 사용 범위 |
|---|---|---|
| Primary / master | 01 | 기본 선, 색, 밀도, 항구 건축, 원근, 작은 여행자 |
| Primary / interior | 04 | 따뜻한 생활실, 낡은 금속과 직물, 거주감 |
| Primary / ship | 07 | 크림·녹슨 주황의 함선, 우주 대기와 효과의 색. 후방 카메라 채택 지시는 아님 |
| Primary / navigation | 11 | 항로실의 실물 소품과 억제된 홀로그램. UI 숫자는 제외 |
| Primary / night | 17 | 비 오는 밤, 젖은 표면, 차가운 주변광과 따뜻한 창문 |
| Primary / winter | 18 | 눈·얼음·차가운 원경. 모든 신규 허브를 설원으로 만들지 않음 |
| Primary / brand | 20 | 주인공·배·도시의 관계와 타이틀 구도. 메뉴는 별도 제작 |
| Secondary | 02, 05, 06, 09 | 술집, 선장실, 정비소, 사막 전초기지의 장소 보조 |
| Support | 03, 08, 10, 12, 13, 14, 15, 16, 19 | 계약·접현·결과·명부·구금·의무·배치·조사의 내용 참고 |

7개 primary를 전부 같은 비중으로 섞지 않습니다. **한 번에 master + 해당 장소 기준 1개, 필요하면 추가 보조 1개**를 사용합니다. 하우징·구금실 같은 support 화면도 나쁜 그림이라는 뜻이 아니라 전체 화풍을 결정하는 자료로 단독 사용하지 않는다는 뜻입니다.

## 3. 형태·색·재료·빛

건축은 오래된 항구의 교량·수직 도크·강철 골조·배관·크레인·계단·수리 흔적을 SF 문법으로 연결합니다. 넓은 도시를 작은 플레이어가 탐험한다는 규모를 지킵니다. 중세 성만 있는 세계, 순수 목조 해적선, 깨끗한 우주 병원, 네온 간판 일색의 사이버펑크로 바꾸지 않습니다.

크림색과 녹슨 적갈·주황은 배와 생활 설비, 회청·슬레이트 블루는 금속과 원경, 호박색은 실내 실용 조명에 사용합니다. 재료는 무광 도장·때 탄 직물·목재 소품·산화 금속의 차이가 보이게 합니다. 플라스틱 같은 광택, 과도한 블룸, 검정 실루엣만 남는 저노출을 피합니다. 레퍼런스의 말뿐인 색명이 아니라 실제 이미지를 보고 농도·대비를 맞춥니다.

## 4. 인물과 배의 일관성

주인공은 배의 소유자이자 성인 조종사입니다. 붉은 갈색 망토/스카프, 실용적인 옷과 여행 장비가 식별점입니다. 같은 캐릭터의 머리·옷·가방·장비 쪽을 작업 시트로 고정하고, 장면마다 재해석하지 않습니다. 게임플레이의 작은 인물과 대화용 큰 인물은 별도 자산이지만 같은 디자인입니다. 시안의 모자/머리/얼굴 차이는 그대로 혼합하지 말고 캐릭터 기준 시트를 먼저 검토합니다.

개인 함선은 크림색 바탕, 녹슨 주황·적갈 패널, 수리 흔적, 산업적 장치가 있는 한 척입니다. 매 장면 새로운 군용 전투기로 바꾸지 않습니다. 파츠는 장착 위치와 전개/수납 상태로 변화를 표현합니다. 글자 'Still Far Enough'를 선체 텍스처에 생성으로 반복해 굽기보다 별도 표기로 처리합니다.

현재 게임의 `voss`/`rio` 등 데이터 ID를 보존합니다. 시안의 Vass/Mira/Rook 이름과 boarding 수치를 조종사·추적자 설정에 자동으로 덮어쓰지 않습니다.

## 5. 시안의 알려진 오류는 복사하지 않는다

04·13 창밖에 자기 함선 전체가 다시 보이는 공간 오류, 12 생포/Dead or Alive 충돌과 임의 보수/6인 정원, 13 조종사에게 붙은 Boarding 점수, 14 선장과 포로의 Rook 이름 중복, 19 추락 운송선에 붙은 자기 배 이름, 20 타이틀의 고정 재화 HUD는 정리 대상입니다. 이 문구들은 공식 세계관이 아닙니다. 반복되는 'brighter tomorrow'류 벽 문구도 스타일의 필수 요소가 아닙니다.

## 6. 산출물과 진행 단계

신규 게임용 배경은 기본적으로 HUD/텍스트/인물 없는 clean plate입니다. 현재 이미지는 UI와 인물이 합쳐진 목표 시안이므로 실제 분리·복원이 필요합니다. 그림에 없는 뒤편·바닥은 복원해야 하고, 물·안개·불빛은 영역 마스크를 갖는 별도 레이어여야 합니다. UI는 Godot에서 실제 텍스트와 버튼으로 구성합니다.

`reference` → `candidate` → `reviewed` → `layered` → `integrated` → `engine_verified`를 구분합니다. 후보를 만들었다고 승인/적용 완료로 표시하지 않습니다. 원본 PNG는 덮어쓰지 않고 새 출력은 버전 경로를 사용합니다. 사용한 reference ID·SHA-256·실제 첨부 파일·프롬프트·캔버스·완료 단계를 작업 기록에 남깁니다.

## 7. 첫 실행 작업

첫 범위는 **녹슨 항구의 clean plate와 레이어 조립**입니다. 새 지역 20장을 더 만드는 작업이 아닙니다. 01을 본 뒤 배경의 HUD/인물 제거·복원, 길과 출입구 배치, 독립 플레이어·NPC, 전경 가림, 영역 한정 수면, 실제 대화를 한 장소에서 검증합니다. 다음 순서는 04 선내 하우징, 이후 07 함선 파츠입니다.

원본 파일이 없으면 ZIP에서 SHA-256 검증 후 복구합니다. 확보 전에는 신규 화풍을 추측해서 만들지 않습니다. 이것이 스타일 혼동 재발을 막는 필수 조건입니다.
